# HAUT Guard 校园网自测清单

这份清单要你在**校园网环境**里跑一遍。客户端的所有加密逻辑已经和 Python 参考实现做过
2615 组逐字节对拍、并通过了独立实现的模拟网关端到端测试，但**真实网关的固件行为**只能由
你在校内验证 —— 尤其是下面标了 ⚠️ 的几项。

填表方式：把「结果」列改成 ✅ / ❌，失败的请在最后「问题记录」里写清现象。
不需要填任何密码到这份文件里。

- 应用版本：`1.0.0`（界面底部「关于」可看到 Electron/Chromium 版本）
- 网关：`172.16.154.130`（portal 69 / status 80），如学校有变动请在设置里改
- 你的环境：Windows 版本 ____________ 是否 Win11 ____________

## C. 状态数据正确性（⚠️ 重点）

| # | 步骤 | 预期 | 结果 |
| --- | --- | --- | --- |
| C1 | 登录后盯着「本次流量」与「在线时长」看 10 秒 | **两个数字都在持续变化**：在线时长每秒 +1；本次流量随实际流量平滑上涨（**不是几秒才跳一次**，也不是几百天的荒谬值） | |
| C2 ⚠️ | 把「在线时长」与你实际连上校园网的时间对比 | 基本吻合（误差在 1 分钟内） | |
| C3 ⚠️ | 把「本次流量」与学校自助服务页面对比 | 同一量级；差别在于客户端统计的是本次会话，自助页面通常显示账号累计 | |
| C4 | 看「累计流量 / 累计时长」小字 | 是账号维度的累计值（通常远大于本次会话） | |
| C5 | 看「账户余额」 | 显示为 `xx.xx 元`；若网关不提供该项，则整项隐藏（不显示 0） | |
| C6 | 看「实时速率」曲线：下载一个文件 | 下行曲线明显抬高（这是**本机网卡**速率）；空闲时贴近 0 | |
| C7 | 看「网关版本」小字 | 显示真实固件版本号（例如 `1.01.20180614`） | |

> 说明：「实时速率」读的是**本机网卡**统计（每 3 秒采样），不是网关的流量 —— 因为网关
> 状态接口的计数字段**几乎不实时刷新**（实测下载 21 MB 都纹丝不动）。所以它包含本机的
> 局域网流量，属正常。
>
> 反过来说，「本次流量 / 在线时长 / 累计流量 / 累计时长」仍来自网关，**可能滞后几分钟**
> 才跳一次数字 —— 那是网关的计费刷新周期，不是界面卡住。

> ⚠️ C1/C2 是这次开发中真实踩到的坑：网关裸文本里 `[3]` 是本次下行字节、`[4]` 是本次上行字节，
> 而不是"累计流量/在线时长"。如果按位置硬解，界面会把 49 MB 的上行显示成「在线 595 天」。
> 现在客户端改为优先取带 callback 的**命名字段**，请你在真机上确认这一项确实合理。

## F. 开机自启

> ⚠️ **先确认这里**：如果机器上还有别的校园网客户端也设了开机自启（注册表
> `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里能看到它），两者会在登录时同时启动。
> 建议只保留一个 —— 多个客户端同时对同一条认证会话动作，容易互相"抢"登录/注销。
> HAUT Guard 的自启项名是 `HAUT Guard`，命令带 `--hidden`（启动后收在托盘，不弹窗）。

| # | 步骤 | 预期 | 结果 |

| F1 | 设置里打开「开机自启」，查看任务管理器 → 启动项 | 出现名为 `HAUT Guard` 的启动项（不显示成一串 appId） | |
| F2 | 注销并重新登录 Windows | 应用自动启动，且**默认收在托盘**不弹窗 | |
| F3 | 关闭「开机自启」后重启 | 不再自动启动，启动项里已消失 | |
| F4 | 手工把 `config.json` 里的 `autoLaunch` 改成 `false`（模拟异常状态）后启动应用 | 注册表里的 `HAUT Guard` 自启项被清掉（启动时会同步纠正） | |

## 已知的、不需要报告的现象

1. 首次启动时 Windows 可能弹「未知发布者」——安装包没有代码签名（签名证书需要额外购买）。
2. 防病毒软件可能对未签名的 Electron 应用报警，属于常见误报；本应用不联网上传任何数据，
   网络请求只有校园网网关。
3. 「实时速率」为空或为 0：需要至少两次状态轮询（默认间隔 30 秒）才有第一个采样点。
4. 在非校园网环境下，「诊断」里的端口连通/状态/令牌三项会失败，这是预期行为。
